# 路网核验记录（成员 A）

## 1. 核验对象
东南大学四牌楼校区 OSM 道路及节点数据。原始数据包含 353 条道路要素、1,616 个节点要素；原始 Overpass 数据时间戳为 2026-11-25T06:07:15Z。

## 2. 拓扑修复方法
使用原始 Overpass JSON 中各 OSM way 的有序 node ID 序列进行拓扑切分。仅当某个 OSM node ID 被至少两个已选道路 way 共用时，才将其作为道路切分点；不以几何坐标相交本身推断道路连通，以避免将立交或不同层级的交叉误判为平面连接。

## 3. 修复结果
| 核验项 | 结果 |
|---|---:|
| 原始道路要素 | 353 |
| 修复后道路分段 | 717 |
| 被切分的原始道路 | 162 |
| 新增道路分段 | 364 |
| 节点要素 | 1,616 |
| 共用 OSM node ID 切分点 | 419 |
| 缺失的道路端点节点引用 | 0 |
| 重复道路 ID | 0 |
| 修复后自环道路段 | 0 |

切分后的道路段保留原始道路的 `one_way`、`speed_kmh` 等属性，并记录来源道路 ID；道路长度按新分段几何重新计算。

## 4. 连通分量检查
在当前选取的道路子集中，以道路端点构建图后得到：
- 端点节点数：557
- 连通分量数：19
- 最大连通分量节点数：515

该统计只针对本次选取并修复的 353 条原始道路，不代表整个四牌楼校区完整路网已断开或不连通。多个分量可能与数据覆盖范围、道路选取范围或实际隔离路段有关，需要结合地图人工检查。

## 5. 尚未完成的现场核验
本次核验不代表已确认：
- 道路当前是否开放、是否施工或封闭；
- 单行方向是否与现场一致；
- 校门、门禁及通行时段限制；
- 道路是否允许消防车或其他应急车辆通行；
- 桥梁、地下通道及不同高程道路之间的实际通行关系；
- 道路宽度、限高、承载能力及实时通行状况。

## 6. 建议的后续检查
1. 在 QGIS 中加载修复后的 roads GeoJSON 与 nodes GeoJSON，检查交叉口和道路端点。
2. 对 19 个连通分量逐一核查，确认是数据覆盖缺口还是实际隔离。
3. 对单行、门禁、封闭状态及应急车辆通行权限，使用学校官方资料或现场调查补充证据。
4. 正式用于应急路径规划前，需由项目团队复核道路可通行性和数据时效性。

## 7. 结论
本次完成了基于 OSM 共享 node ID 的道路拓扑切分，并通过端点引用、道路 ID、自环等结构性检查。结果可作为项目空间数据的拓扑整理版本；不应将其表述为已经完成现场路况或应急通行能力认证。
